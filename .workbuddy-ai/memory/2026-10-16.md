## 夸克下载 502 真根因定位与修复（深夜）

**根因**：`quarkuc.zig` 的 `link()` 用 `return .{ .header = &[_]model.Header{...} }`
返回函数栈帧里的临时数组（运行时值）—— Zig 0.17 不报错但返回即悬垂。代理回源读到
栈残留：`Header.name/value` 的 slice len 变成 16MB 级垃圾，TLS 层按 16KB 上限切成
`17 03 03 40 18`（16408 字节）畸形记录，CDN 回 alert → openlist 侧
`sendBodiless failed: WriteFailed` + 502。

**关键证据**：
- Zig 临时数组返回语义实验（`tools/temp_lifetime_test.zig`）：栈污染后
  `name.len=16786970`，BAD=8/8（悬垂实锤）

- probe3/probe4（std.http.Client 复刻 openlist 调用 + 超时开关）6/6 全部成功 403
  —— 排除 std.http.Client 与 applySocketTimeout
- 设备 tcpdump 4.9.3 抓 ppp0：失败会话反复发 16408B 畸形记录；curl 对照会话
  `t=17 len=3952` → 服务器回 `t=17 len=824`

## 上游错误 message 透传（回归遗留项，同夜修完并验证）

**机制**：`driver.Ctx.err_detail: ?[]const u8`（**值语义**）—— Ctx 活在请求
栈帧上，天然请求级、无并发串台，handler 不用开槽；驱动内辅助函数收
`&ctx.err_detail` 写回；`mapDriverError(res, e, ctx)` 只对**上游类**分支
（WafBlocked/Upstream*/TokenUnavailable）用它当 message。
**状态码保持 502**（我们比 Go 分得细：401/404/409/429/501/507），只有 message
对齐 Go 的 err.Error()。

**落地**：quarkuc 全链路接入 —— **用户配的 `Quark` 是 quarkuc.zig，不是
quark.zig（QuarkOpen 开放平台变体）**，一开始改错了文件。真机验证：上传撞
容量 → 响应 `{"code":502,"message":"capacity limit[{0}]"}`（原为
"upstream error"）。构建 **371/371**（+1 单测 `Ctx.setErrDetail`）。

**三个教训（都踩了）**：
1. 改「读取侧」（mapDriverError）别忘了**写入侧**：第一版只改读取侧就部署，
   验证发现响应没变 —— 驱动根本没写、槽也从未创建。
2. Zig 语法：结构体**字段与声明不能交错**（fn 要放在所有字段之后）；
   `if (a) |x| if (b) x.* = y;` 嵌套 if 赋值不合法，要加大括号。
3. 脚本批量改调用点后要人工过一遍：函数内**没有 `ctx` 变量**的地方
   （resolveEntry/findChild/upAuth/upPart 内部）要用参数名 `err_detail`，
   不是 `ctx.err_detail`；`orelse return` 后直接跟逗号有解析风险，拆两行。

**回归结果**：修复后 e2e **157 通过 / 0 失败 / 2 跳过**（quark 上传由 ❌
变 SKIP —— 只有 message 透出来了，e2e 才能识别「上游容量限制」），UI 9/9。
