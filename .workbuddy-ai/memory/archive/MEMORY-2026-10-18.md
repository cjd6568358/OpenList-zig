# OpenList-zig 项目长期备忘

## Zig 0.17 语言陷阱（真实事故，勿重蹈）

1. **`return .{ .field = &[_]T{...} }` 是悬垂指针**。数组字面量（含运行时值）
   落在被调函数栈帧，函数返回即失效；ReleaseSmall 不报错不崩溃，生产表现为
   「读到垃圾」。**规则：跨函数返回的切片/指针一律用分配器分配**
   （`alloc.alloc` / `a.dupe`）。2026-10-16 夸克下载 502 就是这个
   （quarkuc.zig link()；pan123.zig 同款已一并修）。
2. **TLS writer 的 `flush()` 是「双层刷」**：`std.crypto.tls.Client.writer.flush()`
   只把密文写进**下游 stream writer 的缓冲**（`output.advance`），必须再刷
   底层（`stream_writer.interface.flush()`，或 `std.http.Client.Connection.flush()`）。
   漏了它请求永远不上线、现象是「服务器静默」。client.zig 的 sendOnce 末尾
   `try http_req.connection.?.flush();` 就是为此。
3. **`std.Io.Writer.writableSliceGreedy(len)` 要求 buffer ≥ len**：
   buffer 小于 `std.crypto.tls.Client.min_buffer_len`(16640) 会走
   `defaultRebase` 自旋（ReleaseSmall 下 assert 被编译掉 → 100% CPU）。
   所有承接 TLS 输出的 socket writer buffer 必须 ≥ 16640（用 64KB 最稳）。
4. **`return &v`（v 是 `json.parse` 按值返回的 local）是悬垂指针**——
   `*const json.Value` 返回类型只有两种安全形态：arena 装根节点
   （`const slot = try arena.create(json.Value); slot.* = ...`，itvsh 模式）
   或只返回树内子节点指针（`v.getPath(...)`，子节点在 arena，pan123/quarkuc
   模式）。2026-10-18 pan115 listPage 第三例：读复用栈垃圾（全零 Value）⇒
   fs/list **静默 0 条不报错**；此前能跑是栈布局侥幸，删两行日志改帧布局
   当即引爆。**悬垂指针暴露取决于栈布局，"一直能跑"不是安全证据**。
5. **Go 结构体 tag ≠ 线上 JSON 键的真实大小写**：Go `encoding/json` 键匹配
   大小写不敏感，tag 写 `AccessKeyID` 照样匹配线上 `AccessKeyId`；Zig
   `strAt` 精确匹配 ⇒ 漏。**移植时凡读 JSON 键都要真机抓包验拼写**
   （2026-10-18 115 gettoken.php 事故；其余驱动已全审一遍，无同款）。

## LinkArgs.headers 铁律（2026-10-18，115 全站 403 事故）

- **凡是调 `driver.link(...)` 的入口，都必须传 `.headers = req.headers`** ——
  对应 Go 的 `model.LinkArgs{Header: r.Header}`。115 的下载直链签名**绑定
  User-Agent**：同一 URL，用生成时的 UA 取 = 200，换任何别的 UA = 403
  `invalid signature`（受控实验：同 UA 200 / 换 UA 403，Go/Zig 双侧一致）。
  漏传 ⇒ 驱动拿空 UA 签 ⇒ 回源 UA 不一致 ⇒ 恒 403。
- 已有四处：`api.zig` 的 `fs/get`(1504)、`/d/ /p/`(3729)、archive(1787)；
  `webdav.zig` 三处（302_redirect / 本端代理 GET·HEAD / COPY 取源）。
  **新增下载入口时先检查这一条。**
- **「URL 相同 ≠ 请求相同」**：只对账「生成的 URL 一致」证明不了「回源请求
  一致」。当初误判「上游 CDN 拒签」就是因为只有前者。

## 排查方法论补充（2026-10-18 翻案教训）

- **证据链自洽 ≠ 结论正确，缺的是对照组**。当时有「设备直连 403 + 全头矩阵
  + m115 逐行对账 + Go 源码同构」四条证据仍判错，补上**真 Go 实例 A/B**
  （同文件、同秒、同客户端）一跑就翻案（Go 200 vs Zig 403）。
- **对照实例怎么起**（不碰生产）：设备上 `/opt/sq/openlist/openlist server
  --data /tmp/goab --config /tmp/goab/config.json`（端口换一个）。
  坑：① 空库**不自动建 admin**，要 `OPENLIST_ADMIN_PASSWORD` 环境变量
  或 Web 向导；② `admin set` 与运行中的服务**不能并行**（sqlite 锁住会卡在
  `init logrus...`）；③ API 的 `Authorization` 头放**裸 token**（带
  `Bearer ` 前缀会 `token is invalidated`，只有 WebDAV 处理器兼容 Bearer）；

  ⑤ 自动建号 admin 权限 `0x71FF` 缺 bit9 ⇒ WebDAV PUT/MKCOL 403。

## 全局单例（config）铁律

- **`config.load()` 会把进程单例 `g_config` 指向新配置** —— 测试里
  「save/restore 单例」时，`prev = config.getOpt()` **必须在 load 之前**取；
  取晚了 restore 回去的是已 deinit 的配置，单例悬空（2026-10-16 被 setCors
  每请求读配置踩爆，段错误表现）。`config.setForTest(null)` 收尾同样有效。
- 任何**每请求都读**的全局状态（如 CORS 头）对单例悬空零容忍 —— 写这类代码
  时先想「进程/测试生命周期里它一定有效吗」。

## 上游错误消息透传（driver.Ctx.err_detail）

- Zig `error` 无 payload，上游文本要带出驱动只能走这个字段：
  `driver.Ctx.err_detail: ?[]const u8`（值语义；Ctx 活在请求栈帧上 → 请求级、
  无并发串台，handler 不用开槽）。驱动内辅助函数收 `&ctx.err_detail` 写回。
- `mapDriverError(res, e, ctx)` **只对上游类分支**用它当 message（NotFound /
  NotSupported 等本地判定有明确语义，不吃 detail）。状态码保持既有 502 映射。
- ⚠ **只能在请求线程写**：有 worker 线程的驱动（itvsh 分块上传）跨线程写它
  是数据竞争 —— 要先把消息收回请求线程。
- 用户配置里的 **`Quark` 走 quarkuc.zig**；`quark.zig` 是另一个变体
  QuarkOpen（开放平台），别改错文件。QuarkOpen **不在产物注册表**
  （`driver.zig:349` 白名单有意注释）→ 改它产物 hash 不变属正常；
  验证途径 = 编译 + 单测（不部署）。

## 协议对账铁律（2026-10-17 立，用户驱动，见 STATUS §35）

1. **上游源码是唯一事实来源**，必须落到函数与行号；**不凭"实测感觉"判
   未对齐**。反例：凭一次"PUT 也是 200"把 Go `NoRoute` 的 405 判成未对齐，
   源码一读就翻案（`server/static/static.go:213-227`）。
2. **动态对照一律在设备本机 loopback 上跑**（`tools/dav_compare.py`，
   127.0.0.1:15244 vs :15399）。PC↔光猫走 easytier 隧道，大响应会被 relay
   RST，会把链路抖动误判成服务端问题。
3. **两套错误体系不能混**：
   - JSON API：`common.ErrorResp` → `c.JSON(200, ...)` ⇒ **HTTP 恒 200**，
     错误码在 body 的 `code`（401/403/400/500/429 都一样）。
   - 下载端点（/d/ /p/）+ WebDAV：`ErrorPage` / `ServeHTTP` ⇒ **真状态码**
     + HTML 或 StatusText 纯文本。
4. **下载/WebDAV 的两条分支语义相反**，别混：
   - 本地/内存 = `net.ServeHTTP`（本端切 Range、合成 416、发 Etag、条件请求）；
   - 远程直链 = `common.Proxy` 透明代理（Range 原样转发上游，**上游回 200 就是
     200**，不切片、不合成 416、不补 Accept-Ranges）。
   ⇒ 对云盘的 Range/416/304 一律**不写死断言**，只断言"照抄上游"。
