## CI「裁剪」镜像体积之谜（2026-10-18 深夜排查，用户提问）

**现象**：workflow 产出的「CDN + 裁剪驱动」sqfs 镜像（Release `ci-sqfs-296c3cb`，
资产 `openlist.sqfs_`，20.3 MB）与光猫现役全量 Go 镜像
（`/opt/armbian/bin/openlist/openlist.sqfs` = 21,155,840 B，二进制 88.5 MB，含前端）
体积一致。

**根因**：该 run 是 **push 触发**（296c3cb6 → feat/zhijiadisk），不是
workflow_dispatch。GitHub 的 `inputs` 上下文只在 dispatch/call 时填充，push 时
`${{ inputs.* }}` 全为空串 —— workflow 里写的 `default:`（11 驱动、strip_*=true、
db=sqlite、arch=linux-arm64）只对手动触发生效。连锁后果：
- `--drivers ""` → gen_overlay.py 的 `parse_list("")` 返回 None ≡ "keep all"
  → **87 个驱动全编入**；
- `[ "" = "true" ]` 不成立 → strip_offline / strip_ffmpeg **都没剥**；
- `--db-backends ""` → None → mysql/postgres 没摘；search 同理；
- `arch` 空 → `case "$TARGET"` 全落空 → GOOS/GOARCH 不设 → ubuntu-latest(x86_64)
  上编出 **linux/amd64** 二进制（上设备也跑不了）。
铁证：资产名 `openlist.sqfs_`（模板 `openlist.sqfs_${TARGET}` 后缀空）、release
notes 每个字段全空、同 run `ci-296c3cb` 明写"触发: push / 分支: feat/zhijiadisk"。
CI 全绿是因为没有任何步骤断言 arch 或"裁剪真的发生了"。

**附带发现（Zig workflow 独立 bug）**：`build_zig_minimal.yml` 所有 `zig build`
都在仓库根执行，根目录没有 build.zig（在 zig-src/）→ "Show build.zig options"
步骤即失败 ⇒ **该 workflow 从未产出过任何镜像**。需给相关步骤加
`working-directory: zig-src`；其 drivers 默认空串=全量，与 Go 版默认 11 驱动不一致。

**修复方向**（未动手）：Go 版 env 加兜底 `${{ inputs.arch || 'linux-arm64' }}`
等，或 arch 为空直接 ::error:: 硬失败（静默 amd64 最危险）。
