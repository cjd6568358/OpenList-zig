# 2026-10-30

## 网页端上传报 "network error" —— 根因是 `multipart_enabled` 撒谎（已修并部署）

用户报"天翼云个人和家庭都无法上传，提示 network error"。**不是驱动问题**。

- 前端 4.2.6 的 `Upload-*.js`：上传方式 `[Multipart, HTTP Direct, Stream, Form]`，
  默认取第一个 `available()`；`multipart_enabled=true` ⇒ 默认 Multipart。
  Multipart 对 ≤10MiB 退化成 Stream（`PUT /api/fs/put`），>10MiB 走
  `POST /api/fs/multipart/init` —— **本工程没这条路由** ⇒ `noRoute` 返回
  200 + HTML 外壳 ⇒ 前端 `X()` 只认 `{code:number,data}`，重试 3 次后抛
  `multipart init failed: network error`（全 dist 唯一出处）。
- 实测：`/ecloud_self`、`/ecloud_family` 用 `/api/fs/put` 传 5B/100KB/1MB/2MB/
  5MB/10MB/12MB 全 200，文件真实可见（探针已删）。小文件一直没事，用户试的是大文件。
- 修复：`api.zig` 的 `public_setting_defaults` 里 `multipart_enabled` → `"false"`；
  新增单测钉死该值 + 断言 `POST /api/fs/multipart/init` 仍落 NoRoute。
- 基线：`zig build test` **460 pass / 3 skip**；产物 **1,352,536 B /
  `dc815b20`**（与 10-26 版同尺寸，"true"→"false" 同长度）。
- 部署：按 runbook（数进程=1 → `openlist_start.sh stop` → `mv .new` →
  `sh /opt/script/openlist_start.sh`）→ 14 mounts published，`/api/public/settings`
  里 `multipart_enabled="false"`，12MiB 真机上传 200。
- 文档：STATUS.md 新增 §55，并订正 §22 里"分片上传"和 `fs/form` 两行的旧论断
  （"前端拖拽上传走 fs/put，故不阻塞"是错的）。

### 运维踩坑（新）
- `remote.py` 传命令时 **`/bin/sh` 会被 MSYS 改写成 `C:/Program Files/Git/bin/sh`**
  （因为本机存在该路径）⇒ 远端 ash 报 `C:/Program: not found`。
  用 `sh /opt/script/xxx`（不带前导斜杠）即可；`/opt/...` 这类本机不存在的路径不受影响。
- 本次 `mv -f` 在 ssh 命令串里**没有被 sandbox 拦**（与 10-24 记录不同）。
- 生产 admin token（`zig.token`）可直接当 `Authorization` 用（M13 分支），
  调试时不必登录；`POST /api/fs/put` + `File-Path` 即可做真机上传回归。
