### 踩到的坑（本轮）

- `const copy = ...` 会遮蔽同名 vtable 函数 `copy`；`space` 形参同理。
  驱动文件里给局部变量/形参取名要避开 vtable 函数名。
- `json.Value.null` 是 union 的 tag 字面量，`&json.Value.null` 取到的是
  tag enum 的指针 —— 要 `const v: json.Value = .null;` 再取址。
- **arena 悬垂**：`init(ctx)` 拿到的 `ctx.alloc` 是请求级 arena，init 返回后
  即回收。驱动要长期持有的 `device_id` / `algorithms` 必须深拷到 `self.alloc`
  （本轮写完才发现，已修）。`freeAlgorithms` 要求所有权单一，所以
  normal 变体的默认算法表也必须**深拷**，不能直接存 `&default_algorithms`
  （静态常量被 free 会崩）。
- expert 的 `toJson` 首版漏了 `sign_type` 与 `username` 之间的逗号，
  被 THU-7 的往返测试抓住 —— 手拼 JSON 一定要有 parse 回去的测试。

## 22:05–22:25 迅雷网页版 captcha_sign 破解 + thunder_web 驱动落地

**突破**：`captcha_sign` = 15 轮加盐 MD5 链（纯 JS，无 WASM）。定位链：
service-captcha 模块 609 → utils-async 模块 1643 `a()` → getPubKeySignUtil →
utils-initial 模块 22（导出表）→ 模块 20/21 嵌套包装器 → 模块 0 = blueimp-md5
（在**数组形式**的 `app.<hash>.js` 里，下标即模块 id —— 这是之前找不到模块 0 的原因）。

方法：迷你 webpack runtime 加载真实分片 + 插桩 md5，一次调用打出 15 步全序列，
盐 = 每步输入去掉前 32 字符。两个独立实现（Node / Python）都命中浏览器黄金对；
再拿算出的签名打真实 `POST /v1/shield/captcha/init` → 200 + captcha_token ⇒ 服务端认可。

**修正两条旧结论**：① 「网页 captcha_sign 算法未知」作废；② captcha token 寿命
