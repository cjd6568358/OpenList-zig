### 2. ★ 真机验证抓到两个「定级错了」的活缺陷（当天闭环）

**① 目录句柄 CLOSE 堆越界**——上轮审计把它定为 P2「靠 8 字节对齐 + tag=1
巧合不触发」。真机隔离实例跑 paramiko e2e，`listdir` 的 CLOSE **非确定性**
报 OSError，服务端日志 `sftp: discarding  — a previous write failed`
（vpath 空）。根因：`handleClose` 把 `*DirState`（40 B）`@ptrCast` 成
`*FileState`（~100 B）读 union tag——**结构体更大，tag 读的是分配块外的
堆内存**，垃圾值命中 `.write` + 垃圾 `w.failed` 判真。11-01 全绿只是堆内容
恰好幸运。修：handleClose/handleWrite 入口查 `h.kind` + 回归用例。
**教训：越界读的「不可达」论证必须算结构体大小，不能只看对齐。**

**② 0600 测试 Linux 编译炸 ⇒ 打包机测试闸门自 d41acfcc 起是断的**。
`Io.File.Stat` 无 `mode` 字段（权限在 `permissions: enum(mode_t)`），该测试
Windows 被 comptime 跳过测不出，Linux 一编译就炸。**推论：11-01 的三个
生产构建（9e8a43b0/b7bdef70/b7082785）都没过打包机测试闸门**。修：
`@intCast(@intFromEnum(st.permissions))`。修复后 560/560 Linux 原生全绿，
0600 测试首次真正执行。
